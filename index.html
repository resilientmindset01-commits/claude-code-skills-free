Your agent is fast. That's the problem.

A coding agent will happily agree with your bad idea, write code that passes the tests but is not safe to ship, run a destructive shell command on a long unattended run, and loop forever declaring false victory. These eight skills are the guardrails.

Field notes

The reasoning behind the skills, published in full and free to read. Each one is a specific failure, checked against Anthropic's own documentation or observed directly rather than assumed.

  • Your skill stops working in long sessions — Skill bodies are truncated after compaction, and truncation keeps the start of the file.
  • A CLAUDE.md rule that worked and then stopped — Path-scoped rules do not survive compaction. The project-root file does.
  • Your scheduled task says it succeeded and did nothing — A run that produces no output is not missing, not stuck and not failed. The fourth check.
  • Your cron job fired on the wrong day — Day-of-month and day-of-week are OR-ed, plus dispatch offsets and catch-up runs.
  • Your agent stalled and you lost the work — You probably did not. Flush per item, then finish from the file.
  • Why Claude ignores your CLAUDE.md — Four reasons a rule does not hold, a scope-gap test, and a drift canary.
  • Your agent agrees with everything you say — Why a coding agent validates a bad plan, and how to get a real judgment instead.
  • Auto mode: what actually changed — The permission mode that now starts by default, and which of your allow rules it drops.

FAQ

Do I need to be a developer?

No, but you need to already use a coding agent (Claude Code or similar). The skills assume you run one; they make its output reliable. One skill, review-ai-code, is written for people who read code.

Is this software? Do I install anything?

No. Each skill is a single markdown file (a procedure the agent reads). You copy it into a skills folder -- no dependencies, nothing to run.

It's written for Claude Code, but the Agent Skill format is plain markdown, so it works with any harness that reads skills. The techniques are largely model-agnostic.
